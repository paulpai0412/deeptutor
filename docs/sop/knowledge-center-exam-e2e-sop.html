Knowledge Center → Paper Library／Exam：操作與 E2E SOP

本 SOP 說明 Paper Library 從建立、設定、資料夾整理、單檔／批次／整個資料夾上傳，到 PDF 預覽、題目複核、Original Paper Exam、搬移與刪除的完整操作。Paper Library、Paper Folder、Knowledge Base 與 Question Bank 是不同領域；擷取出的原始題目文字不會因介面語言而翻譯。

驗證範圍：本次 completion audit 驗證的是 deterministic fixture UI suite；未在本次 audit 宣稱執行真實 PDF／LLM release flow。歷史真實驗收紀錄另列於下方，重新驗證時必須明確設定 PAPER_REAL_E2E=1，不可把 fixture 結果當成 real evidence。測試：web/tests/e2e/knowledge-center-exam.e2e.ts。

0. Paper Library 日常操作（繁體中文）

入口：開啟 /knowledge?tab=papers，在 Knowledge Center 的同層分頁選擇 Paper Libraries。/space/questions 保留為原本的 Question Bank，不再作為 Paper Library 入口。

0.1 前置條件與領域界線

  • 必須先建立一個 Paper Library；系統不會偷偷建立預設 library，也不會把單檔上傳放進未知分類。
  • 結構化題目擷取需要可用的 LLM；PDF parser 與 failure policy 必須使用設定頁提供的有效選項。
  • Paper Library 保存來源 PDF 與擷取結果；Question Bank 保存學習紀錄；Knowledge Base 是檢索資源，三者不可互換。
  • 桌面版使用左側 Paper Folder tree、右側安全 PDF 預覽；窄螢幕會先顯示列表，再進入單一 paper 詳情。

0.2 建立 library 與設定

  1. 在 overview 按 New Paper Library，輸入 library 名稱與說明後按 Create。
  2. 選取 library 卡片，確認 URL 含有 library=<opaque-id>&section=papers。
  3. 切換 Settings，設定 library 名稱、說明、Extraction LLM、PDF parser 與 Failure policy，按 Save settings。
  4. 看到「Settings saved」才算保存成功。設定只套用到新上傳與明確執行的 Retry；既有 paper 不會因保存設定而自動重新擷取。
  5. 若沒有 LLM、parser 不可用或 policy 不合法，保留錯誤提示，修正設定後再保存；不要用 Chat 的模型設定取代 Paper Library extraction LLM。

0.3 建立與整理 Paper Folder

  1. 在 Files 分頁按 New root folder 建立根資料夾；在資料夾列按 New child folder 建立子資料夾。
  2. 資料夾名稱會去除前後空白；同一父資料夾下不分大小寫不得重複。/、\\、.、..、控制字元與 traversal 路徑會被拒絕。
  3. 空資料夾也會保留。建立後父資料夾會展開，新資料夾會被選取；可用 Chevron 展開／收合。
  4. Paper 可拖曳到資料夾或 Library root；不便拖曳時，在 paper 的 Move to… 選擇根目錄、同 library 資料夾或其他 library 的資料夾。
  5. 搬移只改變 folder path，不會改變 Paper ID、來源 PDF、題目、複核修正、圖片 asset 或 lifecycle status。處理中的 paper 不可搬移。

0.4 單檔、批次與整個資料夾上傳

  1. 切換 Add files。選一個 PDF 時，該 paper 放在 library root；選多個 PDF 時，每個檔案都是獨立 paper 與獨立 extraction task。
  2. 選擇 Or select an entire folder，或把整個資料夾拖進 drop zone。每個 PDF 的 webkitRelativePath 會轉成 normalized Paper Folder path，缺少的資料夾會自動建立。
  3. 選取摘要會分開顯示 accepted／rejected 檔案；unsupported、unsafe、無法讀取或超過大小限制的檔案會顯示個別原因。可移除單一檔案或 Clear selection，送出時只會提交有效 PDF。
  4. 按 Upload PDFs 後仍留在 Add files；Latest upload status 顯示每份 paper 的路徑、status 與 progress。切回 Files 即可看到 tree 的即時結果。
  5. 批次採逐份處理；一份失敗不會停止其他檔案。失敗的 paper 保留來源，可在 Files 選取檔案後，於預覽 header 按 Retry。

0.5 狀態與復原

狀態意義可操作項目
pending已建立，等待 extraction。可預覽；不可開始 Exam；等待或重試。
processingparser／LLM 正在處理，會顯示進度。可預覽；不可 Move／Delete／Start Exam。
ready可用題目已完整擷取。Preview、Review、Start Exam、Move。
ready_with_warnings可用，但有擷取警告。先查看 warning，再 Preview、Review 或 Start Exam。
partial部分題目可用，部分結果被捨棄或文件未完整涵蓋。可 Review／Start Exam；應先檢查題目與 warning。
failed擷取失敗，來源仍保留。可 Preview、檢查錯誤、修正設定後按 Retry；不可 Start Exam。

0.6 Preview、Review 與 Original Paper Exam

  1. 在左側 tree 選檔案，右側會透過既有 secure source endpoint 顯示原始 PDF；瀏覽器不會取得 filesystem path。使用預覽器的 Open／Download 操作時仍以 opaque Paper ID 請求來源。
  2. 按 Review questions 進入獨立的 full-width child view。依原始順序檢查題號、題目、選項、page、warning 與 related images。
  3. 逐題修改 displayed question number 或 reference answer，按 Save correction；錯誤圖片按 Remove 解除關聯。這只改 extracted metadata，不會修改原始 PDF。
  4. 按 Back to Paper Library 返回同一 paper 的 Preview。Review／Preview 可透過 URL 的 paper／review 狀態恢復。
  5. 只有 ready、ready_with_warnings、partial 能按 Start Exam。Exam 會使用 opaque Paper ID，開啟新的 Chat session；不會把舊聊天上下文當成題目來源。
  6. Exam 仍遵循既有 Original Paper／QuizViewer 行為：依 source order 出題，歷史 snapshot 與 Question Bank provenance 不依賴 live library。

0.7 搬移、刪除與歷史資料

  • 跨 library 搬移時選 destination library 與 folder；若目的 library 已有相同 SHA-256 PDF，API 會回傳 conflict，原 paper 不會被移動。
  • 在 Settings → Danger zone 按 Delete Paper Library，確認瀏覽器確認視窗後才會刪除 live papers、folders、source PDF、questions 與 assets。
  • 若仍有 processing paper，刪除會被拒絕並顯示 conflict；等待完成或失敗後再 Retry／Delete。
  • 刪除 live library 不會刪除 Chat history、Exam snapshot、Question Bank entries 或歷史 attachments；刪除後仍應能讀取既有學習紀錄。

0.8 常見錯誤處理

3. 完整操作步驟與 screenshots

  1. 進入 Knowledge Center 的 Paper Libraries

    操作：開啟 /knowledge?tab=papers，選擇 Paper Libraries tab。

    預期：看到 private library 清單與建立 library 表單；不建立預設 library。

  2. 建立 library 並保存 extraction 設定

    操作：建立本案例 library，選擇實際 LLM option、pymupdf4llm parser，按 Save settings。

    預期：API 保存 LLM profile/model、parser engine 與 keep_partial；LLM 為必要設定。

  3. 選擇並上傳真實 PDF

    操作：選擇上述真實 PDF，確認檔名後按 Upload PDFs。

    預期：Paper record 進入 pending／processing，以背景工作執行真實 parser 與 LLM；不使用 fallback。

  4. 等待背景擷取完成並執行 retry

    操作：選取檔案後，於預覽 header 按 Retry，輪詢 status 並再次等待 terminal status。

    預期：兩次都由實際 extraction pipeline 完成，題目數大於 1；retry 不建立另一個 paper identity。

  5. Paper Review 修正題號／答案並解除圖片關聯

    操作：rename paper；進入 Review，將第一個 image question 的題號改成 一、1-reviewed、保存 reference answer，並按圖片上的 Remove。

    預期：PATCH 只更新 question metadata；PDF 不被修改，圖片 asset 不被當成 PDF 刪除；本案例保留另一題圖片供 Exam snapshot 驗證。

  6. 搬移到另一個 Paper Library

    操作：建立 archive library，在檔案列 hover 後按 Move to…，選擇 archive。

    預期：目的 library 出現同一個 paper_id，原 library 不再列出；hash conflict 與跨 library scope 由 API 保護。

  7. Exam 的 library → paper picker

    操作：從 moved paper 的 Review 按 Start Exam。

    預期：新 Chat session 顯示 Exam settings；Paper Library 與 Exam paper 都選中，composer 的 Knowledge selector 改為 Paper Library 圖示，沒有 Count、Difficulty 或 Type。前端送出的 source 只有 opaque paper ID。

  8. 透過真實 WebSocket 開始 Exam

    操作：按 Confirm；Exam／Quiz 設定確認後會自動送出，不需要再輸入啟動文字或按 Send。

    預期：workspace 顯示第一題，左側歷史 title 使用最新的 renamed paper display name；第一題以原始順序出現，source card 顯示 Exam、renamed paper 與 source question number。backend 先建立 snapshot，再發出第一題。

  9. 逐題作答並保存 Question Bank provenance

    操作：選取第一題答案，按 Check Answer。

    預期：逐題 upsert 保存 library ID/name、paper ID/name、source question number、source type 與 snapshot ID；自動判定為正確時會自動前往下一題；本案例的圖片單選題仍保存為 deterministic／correct 並自動前往下一題；沒有 score、percentage 或 completion result。

  10. 執行真實 AI Judge

    操作：按 AI Judge，等待 real LLM streaming 完成。

    預期：AI judgment 非空並 PATCH 到相同 Question Bank entry，供 reload 與 library delete 後讀取。

  11. 確認 snapshot 圖片與 Next／Previous

    操作：按 Next 再按 Previous；切換到未解除關聯的 image question。

    預期：題目保持原始順序，snapshot attachment URL 可正常載入，不依賴 live paper path。

  12. 刪除 library 後重新讀取歷史

    操作：刪除 archive Paper Library；確認 live paper 與 library API 為 404，reload 同一 Exam session。

    預期：Exam 題目、圖片、作答、Question Bank provenance 與 AI Judgment 仍可讀取；沒有 hard foreign key 阻止刪除，也沒有 cascade 到歷史 attachment／snapshot。

4. 驗收 checklist

  • Release flow 若要驗證真實 PDF、backend、frontend、WebSocket 與網路 LLM，必須另以 PAPER_REAL_E2E=1 執行；本次 completion audit 未執行此 opt-in flow。
  • Library 建立、LLM/parser/failure policy 設定、upload、background polling、Review、retry 均完成。
  • 題號／答案修正、圖片解除關聯、rename、move、library cascade delete 均完成。
  • Exam picker 使用 library → paper；request 驗證 opaque paper ID，不含 filesystem path 或 source_path。
  • Snapshot 在第一題前建立；保存原始順序、題目欄位、library/paper provenance 與必要圖片。
  • 刪除 live Paper Library 後，歷史 snapshot、圖片、作答、Question Bank 與 AI Judge 均可讀取。
  • Exam／Quiz 設定確認後自動開始；包含圖片的單選題也依答案鍵判定，答對後前往下一題。
  • 本功能沒有計分、points、percentage、completion result、statistics 或 ranking。
